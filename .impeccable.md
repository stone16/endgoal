## Design Context

### Users
Technical product builders (founder + small team) managing OKR-driven work
with AI agents. Bilingual CN/EN. Daily/weekly usage. Primary job: "decide
what to work on next" and "tell agents what to do." Not consumer-facing;
this is a builder's tool for people who understand systems.

### Brand Personality
**Calm. Precise. Trustworthy.**

The metaphor: "agent is the contractor, human is the client." The client
walks into a well-run job site where work is happening quietly. When
something needs the client's decision, it is presented clearly and calmly,
not screamed. When nothing needs attention, the interface communicates
"all is well" through deliberate emptiness, not through green checkmarks.

### Aesthetic Direction
**The Quiet Command Center.** The memorable quality: this dashboard is
intentionally sparse when agents are working. It becomes visually active
only when attention is required. The contrast between calm and alert IS
the design. Most dashboards try to look busy and important. This one tries
to look empty and calm.

- **Tone**: editorial, confident, warm-technical. Not corporate. Not playful.
- **Theme**: light mode primary. Dark mode is deferred.
- **Anti-references**: generic SaaS dashboards with cards-in-cards, Notion-style
  information density, "AI slop" (cyan-on-dark, gradients, glassmorphism, glow).
- **Positive references**: Linear's spatial calm, Stripe dashboard's confident
  typography, Apple Weather's "nothing to report" state, a well-designed
  architect's project tracker.
- **Colors**: warm neutrals tinted toward slate. One accent for "your attention."
  Avoid pure black/white. Avoid cool-gray sterility.

### Design Principles
1. **Action over information.** Every screen answers "what should I do next?"
   before "what data is available?" Data is on-demand, not on-display.
2. **Calm by default, present when needed.** The UI feels quiet when agents
   work. Notifications surface with presence, not panic. Empty is intentional.
3. **Honest hierarchy.** Parent above child. Visual weight tracks importance.
   No decorative elements that don't carry meaning.
4. **One surface per job.** Contract edits in one place. Scanning in another.
   Forensics in a third. Never mixed.
5. **Earn every pixel.** If a UI element doesn't help the user decide or act,
   remove it. Whitespace is a feature.
